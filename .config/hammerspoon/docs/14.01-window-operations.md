# 14.01 Window operations

All operations act on the **focused** window and are computed against that
window's **current screen** usable frame (menubar and Dock excluded), so they
work per-display. Implemented in `lua/window.lua` as pure geometry — no `hs.grid`,
no external deps.

## Halves

`h` / `l` / `k` / `j` snap to the left / right / top / bottom half.

## Thirds

- `1` / `2` / `3` — jump directly to the left / center / right third.
- `[` / `]` — cycle across the columns (L → C → R), wrapping. The nearest column
  to the window's current position is the starting point.

## Two-thirds

`4` / `6` — left / right two-thirds (pairs nicely with a one-third window beside
it).

## Quarters

`y` / `u` / `b` / `n` — top-left / top-right / bottom-left / bottom-right quarter.

## Maximize & center

- `m` — fill the usable frame (not true macOS fullscreen, so no separate Space).
- `c` — center the window on its screen, keeping its size.

## Grow & shrink

`=` grows, `-` shrinks, by 5% of the screen (`resizeStep`) about the window
centre, clamped to the screen and to a minimum size.

## Skipped windows

Operations are a **no-op with a brief "skipped" alert** when the focused window
is floating or non-standard:

- apps in the float list (`Neovide` by default — includes the Neovide scratchpad);
- dialogs, sheets, popovers, alerts, and system password/permission prompts
  (detected by window subrole).

This keeps dialogs and the scratchpad from being force-resized. See
[12.01](12.01-architecture-and-configuration.md) to change the float list and
[15.01](15.01-multi-display.md) for cross-display moves.
