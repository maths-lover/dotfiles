# 17.01 Troubleshooting

## Keys do nothing / windows don't move

Accessibility permission is not granted. Enable **System Settings > Privacy &
Security > Accessibility > Hammerspoon**, then reload (`Cmd+Ctrl+R`). If it was
already on, toggle it off/on after an app update.

## `Cmd+Ctrl+Space` opens the emoji picker (or nothing)

That chord is macOS's Character Viewer shortcut. If Hammerspoon isn't running or
lacks Accessibility, macOS handles it instead. Start Hammerspoon / grant the
permission — or rebind `M.entryChord` in `lua/config.lua`
(see [13.01](13.01-keybindings.md)).

## "skipped" alert when I try to snap

The focused window is floating or non-standard: a float-listed app (Neovide,
including the scratchpad) or a dialog/sheet/popover/prompt. This is by design.
Adjust the float list in `lua/config.lua` if needed.

## Config edits don't take effect

Auto-reload watches the resolved repo path. Confirm `~/.config/hammerspoon` is a
symlink into the repo (`ls -l ~/.config/hammerspoon`) and that you ran
`stow --restow .`. Force a reload with `Cmd+Ctrl+R`. Check the Hammerspoon Console
(menubar icon) for red errors.

## Doesn't start at login

`hs.autoLaunch(true)` registers the login item only after the **first manual
launch**. Open Hammerspoon once. Verify under **System Settings > General > Login
Items**.

## Menubar icon missing

Set it back: `defaults write org.hammerspoon.Hammerspoon MJShowMenuIconKey -bool true`,
then relaunch Hammerspoon.

## "one display" when moving to another screen

Only one display is connected. Move-to-display needs a second monitor; focus and
snapping still work on the single screen. See
[15.01](15.01-multi-display.md).

## Reset

Quit Hammerspoon, `cd ~/dotfiles && stow --restow .`, reopen Hammerspoon, and use
the Console to read any load errors.
